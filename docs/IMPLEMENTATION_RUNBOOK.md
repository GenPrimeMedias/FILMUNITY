# UNI360 — First Milestone Implementation Runbook

This runbook covers repository creation, CI and Laravel bootstrap only. It does not implement membership or business modules yet.

## Phase A — Create GitHub organisation and repository

1. Create a dedicated GitHub organisation or use a dedicated account-owned repository if appropriate.
2. Create a public repository named `uni360`.
3. Initialise without GitHub-generated README/licence if you will push this prepared scaffold.
4. Set repository description: `Open-source multi-tenant association and union management platform for the South Indian film industry.`
5. Add topics: `laravel`, `postgresql`, `multi-tenant`, `association-management`, `membership-management`, `open-source`, `south-india`.
6. Push the scaffold and set `main` as default branch.
7. Enable Issues, Discussions (optional), and private vulnerability reporting.
8. Protect `main`: require pull requests, require CI checks, block force pushes and deletion. If working alone, use a documented self-review process until independent reviewers join.
9. Enable secret scanning and push protection if available on the selected GitHub plan.
10. Add a security contact in repository settings.

## Phase B — Install prerequisites

Use supported, mutually compatible versions of:

- PHP 8.3 or later as required by the selected Laravel 13 release;
- Composer 2;
- Node.js LTS compatible with the selected frontend toolchain;
- PostgreSQL 16+;
- Git;
- Docker Desktop or Docker Engine (recommended).

Verify versions:

```bash
php -v
composer --version
node -v
npm -v
psql --version
git --version
docker --version
```

## Phase C — Create Laravel application

From a clean workspace:

```bash
composer global require laravel/installer
laravel new uni360
cd uni360
```

During the Laravel installer prompts:

- choose the **React** starter kit (React + TypeScript + Inertia);
- choose the built-in Laravel authentication option for the initial baseline;
- choose Pest or PHPUnit consistently with the team preference;
- choose PostgreSQL where the installer offers database configuration, or configure it immediately afterward.

The current official React starter kit includes React, TypeScript, Inertia, Tailwind and shadcn/ui. It is preferable to assembling these integrations manually. See the official [Laravel 13 starter-kit documentation](https://laravel.com/docs/13.x/starter-kits).

If the installer version differs from the current docs, follow the prompts and official docs for the installed Laravel release.

````

Confirm the installed Laravel version and PHP constraints before proceeding:
```bash
php artisan --version
composer show laravel/framework
````

If the selected Laravel starter kit supports the desired React + TypeScript + Inertia stack for the current release, use its official React starter kit. Review generated dependencies and scripts rather than blindly accepting defaults. Keep frontend package versions locked.

Configure PostgreSQL in `.env`:

```dotenv
DB_CONNECTION=pgsql
DB_HOST=127.0.0.1
DB_PORT=5432
DB_DATABASE=uni360
DB_USERNAME=uni360
DB_PASSWORD=local_only_change_me
```

Create the local database/user securely. For Docker-based local development, use the supplied `docker-compose.dev.yml` and do not reuse its sample password outside local development.

Then:

```bash
cp .env.example .env
php artisan key:generate
php artisan migrate
npm install
npm run build
php artisan test
```

The exact scripts may differ depending on the official starter kit generated. Update README and CI to match the actual generated `package.json` and Composer scripts.

## Phase D — Add the scaffold

Copy the documentation, governance, GitHub workflow and configuration files from this project pack into the Laravel root. Merge `.gitignore` carefully with Laravel's generated file; do not replace framework-required ignores blindly.

Check:

```bash
git status --short
git diff --check
```

Ensure `.env`, database files, local storage, logs and secrets are not staged.

## Phase E — Configure CI

1. Inspect the GitHub Actions workflow generated by the selected Laravel starter kit; merge rather than duplicate useful checks.
2. Add or adapt `.github/workflows/ci.yml`.
3. Inspect the Laravel-generated `composer.json` and `package.json`.
4. Ensure the workflow's PHP extensions match actual dependencies.
5. Ensure `npm ci` is supported by a committed `package-lock.json`.
6. Add explicit `typecheck` and `lint` scripts rather than relying permanently on optional checks.
7. Run CI locally where practical, then push a branch and open a pull request to validate GitHub Actions.
8. Pin third-party GitHub Actions to full commit SHAs before treating the workflow as hardened production CI. The scaffold uses readable version tags for initial setup.

## Phase F — Git initialisation and push

```bash
git init
git add .
git diff --cached --check
git commit -m "chore: establish UNI360 project foundation"
git branch -M main
git remote add origin https://github.com/YOUR-ORG/uni360.git
git push -u origin main
```

Replace `YOUR-ORG` with the actual GitHub organisation. Do not publish until the licence, project ownership/copyright notice and repository visibility have been reviewed.

## Phase G — First pull request validation

Create a branch and make a small documentation or health-check change. Open a PR and verify:

- CI starts for pull requests;
- PostgreSQL service becomes healthy;
- Composer install completes;
- migrations run on a clean database;
- Laravel tests pass;
- frontend install and build pass;
- no secret scanning alerts appear.

## Phase H — First milestone exit checklist

- [ ] Public repository and project description configured.
- [ ] Apache-2.0 licence reviewed and committed.
- [ ] README and architecture docs published.
- [ ] Contribution, governance and security policies committed.
- [ ] Laravel 13 application boots locally.
- [ ] PostgreSQL connection and clean migrations work.
- [ ] React/TypeScript/Inertia frontend builds.
- [ ] CI passes on pull request.
- [ ] Main branch protection enabled.
- [ ] No OTT code, credentials, production data or media assets are present.
- [ ] Clean-clone setup instructions verified by another developer if possible.

## Not in this milestone

Do not yet build finance, welfare, grievances, elections, tenant RLS, payment integration or OTT-related features. The next milestone should design and implement organisation identity, tenant context and RBAC with security tests before adding member records.
