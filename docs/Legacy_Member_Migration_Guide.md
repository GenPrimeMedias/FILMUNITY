# Moving an association from its old software to FILMUNITY

Phase 1 now provides a preview-only XLS, XLSX and CSV upload/mapping screen under Members → Legacy membership import preview. It does not commit imports or create staging records. Numbering is available for separately reserving the legacy series; preview never advances or configures it.

## Phase 1 preview workflow

### Download the current FILMUNITY template

The working preview screen provides a blank XLSX, UTF-8 CSV equivalent and filled synthetic XLSX example. Use the Members sheet (index 0), header row 1. Its exact accepted headers are `number,name,email,phone,address,category,starts_on,ends_on`; they map automatically when each is present exactly once. Explicit manual mappings override automatic detection. Other-software exports retain the existing manual mapping workflow.

The older `Legacy_Member_Mapping_Template.csv` is a planning/source-history reference, not the current upload template. Its `membership_number`, `full_name`, `membership_type`, `joined_at` and `valid_until` require manual mapping to the accepted fields. Its source IDs, status, payment-history, document and decision-note columns are not accepted import fields. The current template deliberately does not copy them into the data sheet.

The Guidance sheet documents required/optional fields, category values, dates, timezone selection and preview limits. Status import is unsupported; no membership status is assigned. Source-reference examples live only on Guidance and are formatted as text, as are member-number and phone columns. The workbook uses date-only cells with yyyy-mm-dd display. CSV carries no Excel cell formats, so select Text for identifier/contact columns when opening it in Excel. A source timezone must still be selected explicitly in the preview.

Workbook assets in `resources/templates/legacy-membership` are generated by `scripts/build-legacy-membership-templates.mjs` from `LegacyMembershipTemplate::definition()` and the importer's field/category constants. The artifact-tool runtime is development tooling only, not a PHP/application dependency. Rebuild after changing the accepted schema and run the download/preview round-trip test. No membership, numbering, financial or schema changes are made by downloads or preview.

Choose an association you administer, upload a file (maximum 2 MB), select the worksheet and header row, and read its columns. Map legacy number, full name, email, membership category and validity dates. Phone/address can be shown as source contact context; the current user model has no native destination fields for them. Select the original source timezone explicitly. CSV must be UTF-8; comma, semicolon and tab delimiters are supported. Preview is limited to 2,000 source data rows and 64 columns, with no silent truncation.

Select Validate mapped rows. The summary separates rows ready for later import review, existing association matches, corrections and manual identity reviews. Every flagged row includes its original source row and reasons. Duplicate numbers are compared case-insensitively but the original string, including leading zeros, is retained. Shared source emails and ambiguous number/name/email matches are routed to review; no global user lookup reveals another association's records. Existing matches are informational and never overwrite member data.

Store identifiers as text in the source workbook. XLSX pure zero-padding masks are preserved; numeric IDs whose original zeros or precision cannot be established are flagged. Previously lost digits cannot be reconstructed. Formula cells are not evaluated and mapped formula values are blocked, including XLS formulas with blank cached results. Use Yearly or Life-Time categories and date-only Excel cells or YYYY-MM-DD strings. Yearly records need a validity end after the start; Life-Time records must have no end. Missing required fields or source timezone require correction. This phase does not infer verified identity, renew expired membership or provide a commit action.

Uploads are parsed directly from private request-temporary files and are not retained. XLSX packages are bounded by entry count/expanded size; XML entities and macro packages are rejected. Genuine binary XLS is required; renamed HTML/CSV is rejected. No member, payment, receipt, financial balance or numbering writes occur. Synthetic fixtures exercise all three formats against filmunity_test. No schema migration is required for this preview release.

## 1. Agree on the cutover and number series

Choose a cutover date/time and the person authorised to approve the import. Identify every legacy number series, including inactive/expired members and numbers intentionally reserved or never reused. Set the FILMUNITY next number above the highest reserved legacy numeric sequence. Do not use the member count as the last number: gaps are common.

| Old last-issued number | Prefix in Workspace setup | Next member number | Minimum digits | New FILMUNITY number |
| --- | --- | --- | --- | --- |
| SISA-6000325 | SISA- | 6000326 | 0 | SISA-6000326 |
| TFPC-9623 | TFPC- | 9624 | 0 | TFPC-9624 |
| 999 | empty | 1000 | 0 | 1000 |
| ABC-000999 | ABC- | 1000 | 6 | ABC-001000 |

If new FILMUNITY members must be added before importing old members, reserve the whole legacy range first. Example: legacy numbers run up to SISA-6000325, so start new issuance at SISA-6000326. Later imports must preserve their old values and never allocate new numbers from the live counter. Updating configuration does not renumber current members or change old receipts.

## 2. Export and keep a read-only original

Export from the old application's own reporting/export tool. XLSX is preferred for a structured workbook. If it only produces XLS, open it in Excel or LibreOffice and save a working copy as XLSX. Keep the original export untouched and record its source system and export date. Do not enable macros. Do not upload files to an unimplemented endpoint or insert them directly into the production membership tables.

Keep membership records, custom answers, documents and financial history as separate sheets/files with stable source IDs. Keep a count of records per association, type and state. Include expelled/suspended/expired records if the association needs them for audit, marking their state accurately.

## 3. Prepare the mapping

The included `Legacy_Member_Mapping_Template.csv` is an Excel-compatible planning template, not an executable import. Open it through Excel's Data → From Text/CSV with UTF-8 and set identifiers, phone numbers and membership numbers to Text. Save your working workbook as XLSX. Preserve Tamil and other Unicode names. Replace the sample rows.

| Source field | Proposed destination / handling |
| --- | --- |
| Source system and source member ID | Stable import identity, unique per association/source; needed for safe re-runs |
| Existing membership number | Preserve exactly as Text, including prefix and leading zeros |
| Name | Link to or create the appropriate global identity after review |
| Email | Candidate identity match, never proof of ownership by itself |
| Phone | Text; preserve +91 and leading zeros |
| Yearly / Life-Time | Map to the existing membership types |
| Joining date | Original joining date, distinct from import timestamp |
| Validity end | Explicit date/time and timezone for yearly members; empty for Life-Time |
| Status | Active or suspended, with expiry derived from validity; review unusual legacy states manually |
| Department / profession / custom fields | Map to stable association form-field IDs, not just labels |
| Old payment references and receipts | Separate legacy history with provenance; never fabricate a new bank proof or new receipt |
| Document filename / source path | Map via a manifest to privately stored files after file validation |
| Reviewer decision notes | Preserve source author/date when known; distinguish from FILMUNITY decisions |

Do not import passwords or assume a previous app's password hashes are compatible. Do not replace an existing FILMUNITY user's profile, merge accounts automatically, grant association-admin roles, or mark email verified simply because a spreadsheet contains an address.

## 4. Validate in a staging import

The importer should provide a preview showing rows ready to import, warnings and blocking errors, without sending email or changing memberships. Required checks:

- Association tenant is selected by the authorised admin, never trusted from a spreadsheet column.
- Duplicate membership numbers are checked case-insensitively within that association, including existing FILMUNITY records and rows in the upload.
- Duplicate source IDs are blocked; a repeated upload must not create another membership.
- Email collisions, shared family/office addresses and missing emails go to manual identity resolution.
- Yearly dates are consistent. Life-Time has no end date. Preserve expired status, rather than granting a fresh year at import time.
- Leading zeros, Unicode, large numbers and date formats survive unchanged. Use explicit dates and the source timezone, not Excel display formatting alone.
- Existing member-number ranges remain reserved even if some old rows are excluded from the first batch.
- Documents are validated by actual file type/size, scanned where supported, stored privately and exposed only through authorised download routes.
- Spreadsheet formula cells are not executed; exported user-supplied values beginning with formula characters are written safely as text.

The current native membership schema requires an initial FILMUNITY payment reference. The import increment must add explicit legacy provenance and a valid legacy membership path. **Do not invent a paid transaction, backdate a new FILMUNITY receipt, or misuse zero-fee activation to import paid legacy history.** Preserve original proof/receipts as legacy evidence instead.

## 5. Pilot and reconcile

Use an isolated staging database and one association first. Try a small pilot covering an active yearly member, expired member, Life-Time member, suspended member, leading-zero number, Tamil name, missing email and duplicate conflict. Verify that only valid active members can enter a workspace. Confirm existing users do not gain rights to other associations.

Compare total counts, member numbers, validity dates and original financial references with the export. Check documents and decision notes. Have the association administrator sign off on the preview and reconciliation report.

## 6. Final cutover

Take a verified backup. Stop legacy writes or agree on a change log. Export a final delta, validate it and show the concrete commit preview. An authorised admin then commits the import batch. Each batch should retain file hash, uploader, source ID, imported row IDs, timestamps, counts and a downloadable error/reconciliation report. A re-run should skip already imported source IDs rather than overwrite live records.

Send invitations only as a separate explicit action after import approval. Members should claim/link identities through verification. Imported membership status must never grant platform or association administration privileges.

Keep the old application read-only until the association confirms reconciliation. Preserve the source backup and audit report according to the association's retention policy. Rolling back an import must target its batch and avoid deleting records that subsequently gained payments or activity.
